# Falcon-512 verification with vector intrinsics

An experiment comparing [blueshift-gg/solana-falcon512](https://github.com/blueshift-gg/solana-falcon512)
(scalar sBPF, `ed45663`) with the same verifier where the arithmetic runs on the experimental vector
intrinsics (SIMD-0645 style static calls, see `../docs/simd-experiment.md`).

`program/` takes the same instruction data and embeds the same compile time prepared pubkey as
Blueshift's example program, with Firedancer's verifier structure (`fd_falcon.c`, branch
`drubin/falcon-syscall`) written for the vector intrinsics:

* **Signature decompression:** Firedancer's windowed decoder. A 64 bit big-endian window and one
  lookup in a 4096 entry table per coefficient (sign, low bits and the unary high bits of every code
  up to 12 bits long), four coefficients per window, two windows per loop iteration. A longer code
  (rare) has length 0 in the table, so it repeats into the window's later lookups: one test of the
  last entry per window instead of one per code, then the long code is decoded inline. sBPF
  has no count-leading-zeros, the table replaces it. Output: signed 16 bit coefficients in a buffer,
  loaded into the vector file with one 32 slot `load256`.
* **SHAKE-256 hash-to-point:** a vectorized Keccak-f[1600] on one state with 512 bit operations on
  64 bit lanes, one state row per slot pair. Theta with `ternlog512` / `permd512` / `rolv64x8`, rho
  with `rolv64x8`, pi as one lane permutation per row (which yields the column layout), chi in place
  with `ternlog512`, and `transpose8x8q` back to rows: 28 vector ops per round. Two of the copies
  the round needs are free: pi also copies row 4 into the unused lane 5, so the transpose leaves a
  copy of row 4 in the unused row 5 for the column parity to accumulate on (two `ternlog512`), and
  pi writes column 0 to a spare pair, so one `xor512` both copies it back for chi and applies
  iota. The rate goes in and
  in without scalar byte work: a full block is one 4 slot `load256` plus `ins64` for lane 16, spread
  over the rows with `permt2d512` / `permd512` (only the last, padded block goes through a buffer). Rejection sampling stays in vector registers: per rate row a
  `shufb512` byte swaps the big-endian samples, `cmp512` compares them with 5q (unused lanes have
  threshold 0), `compress512` keeps the accepted ones in order and returns their number, and one
  store appends them to the candidates.
* **NTT, pointwise product, norm:** Cooley-Tukey forward / Gentleman-Sande inverse NTT over
  Z/12289 like Firedancer, written the way current AVX2 NTTs (Kyber, Dilithium) are: 16 signed
  16 bit coefficients per slot, Montgomery products as one `mont16` op (4 AVX2 instructions), lazy reduction
  where a tracked bound requires it, levels 8 / 4 / 2 after an 8 x 8 transpose of coefficient pairs,
  level 1 inside the pairs. Everything runs on 512 bit slot pairs except the two levels between the
  slots of a pair and the transposes. The norm sums squares with `madd16`. Firedancer computes
  NTT(h) per call, here it is part of the prepared pubkey. The twiddles of 8 butterfly groups come
  in with one 32 slot `load256` (instead of a load or two broadcasts per group).

The vector file is private VM state: the program moves data between guest buffers and slots only
with `load256` / `store256` (up to 32 slots each).

All vector code is generated by `program/build.rs` as straight-line calls with constant slot numbers
(so the JIT lowers every call inline). The build script simulates the generated code and checks it
against schoolbook polynomial multiplication (including the extreme coefficients, with an overflow
and bound check of every 16 bit op), a reference Keccak-f and a reference SHAKE-256 before the
program is built.

## Results

64 PQClean signatures (messages of 0 to 1000 bytes), each verified by both programs on every engine,
tampered messages and signatures rejected, CUs identical between interpreter and JIT.

| | Blueshift (scalar sBPF) | Vector intrinsics |
|---|---|---|
| CUs, median (min, max) | 182,764 (172,264, 254,225) | **22,029** (20,460, 31,872), 8.3x fewer |
| Program size | 99 KiB | 79 KiB |

Where the CUs go (135 byte message, 23,442 CUs): Keccak-f 13.45k (10 permutations of 1,345), the
signature decoder 6.4k, the NTT / product / norms 2.2k, sampling, absorbing and glue 1.3k.

## Reproduce

```sh
# programs (prebuilt copies are in fixtures/)
(cd program && cargo-build-sbf --arch v3 && cp target/deploy/falcon_simd.so ../fixtures/)
# Blueshift's program: git clone https://github.com/blueshift-gg/solana-falcon512 && (cd program && cargo-build-sbf --arch v3)
# signatures (PQClean via pqcrypto-falcon, key from Blueshift's fixtures)
(cd gen-fixtures && cargo run --release)
# benchmark: verifies every signature with both programs on every engine, then times them
cd .. && cargo bench --features simd-experiment --bench simd_falcon   # -> target/simd-bench/falcon.json
```
