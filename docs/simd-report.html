solana-sbpf · simd-experiment · BLAKE3 · AMD EPYC 9454P

Vector intrinsics in the sBPF JIT, on real x86

The experiment adds 13 vector instructions, a 2 KiB vector region at 0x6_0000_0000, and a JIT that lowers each instruction to one native AVX2 instruction. On a Zen 4 EPYC, BLAKE3 at 1 MiB runs at 980 MiB/s with the register-cached JIT, against 19.7 MiB/s for scalar sBPF in the same JIT.

The three variants

Scalar against intrinsics in the vector region

A · scalar sBPF, JIT

BLAKE3 written in ordinary 32-bit sBPF ALU instructions. The 16-word state doesn't fit in sBPF's 10 registers, so it lives in the heap. Each G function does about 10 loads and stores, and every load or store in this JIT goes through bounds-checked address translation.

D · intrinsics + vector region, direct JIT

The same algorithm on vector ops (vadd32x8, vxor, vror32x8 and others), 8 chunks in parallel. Vector slots have fixed addresses in the region, so the JIT addresses them directly. Every op loads its operands from the region and stores the result back.

E · intrinsics + vector region, register-cached JIT

The same program again, but the JIT keeps slots resident in ymm0–ymm14 within a basic block. It writes them back only at block boundaries, before host calls and on eviction.

F · native blake3 crate

Shown only as a reference ceiling. It's the host's hand-tuned SIMD implementation, which an onchain program can't call.

Full hash throughput

MiB/s by input size

Below 8 KiB there is no full group of 8 chunks, so D and E run the single-state kernel: one BLAKE3 state, one row per vector. From 8 KiB they switch to the 8-way kernel, which explains the step.

What the JIT emitted

The 8-way cached kernel still spills: 32 live slots (16 state plus 16 message words) compete for 15 YMM registers under plain LRU eviction. The single-state kernel fits and barely touches memory, which is why caching gives it 5× and the 8-way kernel only 1.7×.

Each vector instruction is metered at 1 CU, like any other instruction. That's a provisional pricing choice, so these figures aren't evidence of speed.

Method and open questions

How it was measured

  • Each value is the median of 15 samples. Each sample batches enough warm runs to last at least 2 ms. JIT compile time is the median of 7 cold compiles.
  • Inputs are identical for every variant, and each benchmark checks its digest against blake3::hash.
  • TSC ticks per byte come from rdtsc. On this part the TSC runs at about 2.75 GHz while cores boost higher, so ticks aren't core cycles.
  • No sol_math-style syscall was built, so this report doesn't claim the intrinsics beat a syscall.
  • Remaining gap to native: flushes around the 16 message loads per block, two transposes per block, spills in the 8-way kernel, and scalar tree logic.
